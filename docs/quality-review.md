# 品質チェックの記録

チェックのやり方は、スキル `quality-check`。結果は、日付の見出しをつけて、下に書き足していく。
問題は 3 つに分ける: **まちがい**（要件・ドキュメントとのずれ、不具合）／**標準から外れている**（ふつうのやり方と違う）／**今後の改善**（今は困らないが、大きくなったら直したい）。

### 直したこと

- 直したあとの確認: モックのスクリプトは構文チェックと oxlint で警告 0 件。編集中の検索・新規保存・保存・全文の開閉・ラベルを、ヘッドレスブラウザで自動確認した。画面のスクリーンショットでも、見た目が変わっていないことを確認した。

### 振り返り（1 回目を終えて）
- **価値があった**: 設計ドキュメントの決めごとの補足（I-1〜I-4）、秘密情報・リポジトリ設定の確認、CLAUDE.md の古い記述の修正。実際のアプリに引き継がれる。
- **価値が小さかった**: モックのコードの細かい直し（S-1〜S-4）。モックは使い捨てで、本物は React で作り直すため、磨いても残らない。トークンの無駄だった。

- **今後の方針**: コードはしっかり、設計ドキュメントは軽く、使い捨てのモックは行わない。詳しくは [README](../README.md) の再開メモ。

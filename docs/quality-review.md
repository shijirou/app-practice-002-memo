# 品質チェックの記録

チェックのやり方は、スキル `quality-check`。結果は、日付の見出しをつけて、下に書き足していく。
問題は 3 つに分ける: **まちがい**（要件・ドキュメントとのずれ、不具合）／**標準から外れている**（ふつうのやり方と違う）／**今後の改善**（今は困らないが、大きくなったら直したい）。

---

## 2026-11-16 1 回目（設計ドキュメントと画面モック）

アプリのコード（React・Spring Boot）はまだ無いので、フロントエンド・バックエンドのチェック（lint・ビルド・SpotBugs・テスト）は対象外。
代わりに、設計ドキュメント同士の食い違い、画面モックの動きと使いやすさ、公開リポジトリの安全面を調べた。

### 全体の評価
- **よい所**: 秘密情報・実在の個人情報は見つからなかった（git の履歴のメールも noreply）。シークレットスキャン・プッシュ保護は有効で、main のルールセットも動いている。要件定義書・データ設計・画面デザイン・モックは、おおむね同じ内容で揃っていた。
- **気をつけたい所**: モックは、実際に動かして試すと、編集の途中の操作に弱かった。設計ドキュメントは、「失敗したときの返し方」や日時の扱いなどの決めごとが足りなかった。アプリを作る前に埋められたのは、いいタイミング。

### 直したこと
- モック: 編集中の書きかけを守る（M-1・M-2）、ラベル・ボタン化・読み上げ対応（S-1〜S-3）、警告の解消（S-4）。
- ドキュメント: CLAUDE.md を現状に合わせた（M-3）。データ設計に、日時・失敗の返し方・検索の記号・文字数・重要の窓口を追加した（I-1〜I-4）。ペルソナに「重要」を追加し、クライアント情報に、質問への回答案の場所を追記した。
- `.gitignore`: 個人設定を除外（I-5）。
- 直したあとの確認: モックのスクリプトは構文チェックと oxlint で警告 0 件。編集中の検索・新規保存・保存・全文の開閉・ラベルを、ヘッドレスブラウザで自動確認した。画面のスクリーンショットでも、見た目が変わっていないことを確認した。

### 振り返り（1 回目を終えて）
- **価値があった**: 設計ドキュメントの決めごとの補足（I-1〜I-4）、秘密情報・リポジトリ設定の確認、CLAUDE.md の古い記述の修正。実際のアプリに引き継がれる。
- **価値が小さかった**: モックのコードの細かい直し（S-1〜S-4）。モックは使い捨てで、本物は React で作り直すため、磨いても残らない。トークンの無駄だった。
- **記録しておく価値があった**: M-1「編集の途中の書きかけが、一覧の描き直しで消える」。モックの直しではなく、**本物を作るときの注意点**として残す（編集中の文字を state に持ち、描き直しで失わない。検索などほかの入力からカーソルを奪わない）。
- **今後の方針**: コードはしっかり、設計ドキュメントは軽く、使い捨てのモックは行わない。詳しくは [README](../README.md) の再開メモ。

## 2026-11-16 2 回目（スライス 1 のコードレビュー・PR #14）

アプリのコードができたので、コードレビュー（`/code-review medium`）を行い、指摘 8 件を確かめて、すべて直した。
方針どおり、コードはしっかり行った。直したあとは、API のテスト 18 件・画面のテスト 19 件・lint・ビルドを回し、本物の API・画面・ブラウザで通しの確認をした。

### 結果
| 項目 | 結果 |
|---|---|
| 対象 | `backend/`（Spring Boot）・`frontend/`（React）・設定ファイル |
| 道具 | コードレビュー、Gradle（テスト）、Vitest、oxlint、Edge のヘッドレス実行（通しの確認とコンソールのエラー集め） |
| 指摘 | 8 件（すべて実際の問題だった。すべて直した） |
| テスト | API 11 → 18 件、画面 15 → 19 件。元の不具合を戻すと、新しいテストが失敗することを確認 |

### 全体の評価
- **よい所**: 失敗の返し方が全 API で同じ形、入力チェックと文字数の数え方が設計どおり、テストが本物の PostgreSQL を使っている。
- **気をつけたい所**: 「画面の状態と、サーバーの状態がずれる」場面（読み込み中・保存中・失敗後）の扱いが甘かった。小さなアプリでも、通信が絡む画面では、順番とやり直しを考える。

### まちがい（直した）
| # | 場所 | 内容 | なぜ問題か | どうしたか |
|---|---|---|---|---|
| R-1 | 画面 `App.jsx` | 最初の読み込みに失敗したあとに保存すると、一覧が「保存した 1 件だけ」になり、前からあるメモが隠れた。読み直しと保存が重なると、古い結果が新しい結果を上書きする | メモが消えたように見え、件数も嘘になる | 保存のあとは一覧を読み直す。読み込みに順番の札を付け、古い結果は捨てる |

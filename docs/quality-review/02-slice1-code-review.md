## 全体の評価
- **よい所**: 失敗の返し方が全 API で同じ形、入力チェックと文字数の数え方が設計どおり、テストが本物の PostgreSQL を使っている。
- **気をつけたい所**: 「画面の状態と、サーバーの状態がずれる」場面（読み込み中・保存中・失敗後）の扱いが甘かった。小さなアプリでも、通信が絡む画面では、順番とやり直しを考える。

| R-1 | 画面 `App.jsx` | 最初の読み込みに失敗したあとに保存すると、一覧が「保存した 1 件だけ」になり、前からあるメモが隠れた。読み直しと保存が重なると、古い結果が新しい結果を上書きする | メモが消えたように見え、件数も嘘になる | 保存のあとは一覧を読み直す。読み込みに順番の札を付け、古い結果は捨てる |
